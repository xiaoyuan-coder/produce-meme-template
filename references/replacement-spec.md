# 第一阶段替换与生图规范

## 1. 适用范围

本规范负责回答两个问题：

1. 网图中的什么内容需要替换。
2. 应该替换成什么，以及如何编译成可批量调用生图 API 的 prompt。

用户或批次提供策略时，Skill 按策略执行并完成合同检查。未提供策略时，Skill 依据本规范自主决定。所有决定都写入 `ReplacementPlan`，禁止把临时判断只留在对话或自然语言日志中。

## 2. 决策优先级

```text
单图显式策略 > 批次显式策略 > Skill 自主策略
```

显式策略分为：

- **指定替换值**：明确某个目标替换成什么。
- **指定分配规则**：明确 IP 池、人群、主题、媒介或组合比例，由 Skill 做单图分配。
- **指定保留项**：明确文字、语言、关系、构图或某个文化锚点保持不变。
- **指定禁止项**：明确不能出现的身份、物种、品牌、风格或表达。

冲突时依次检查：用户最新单图指令、用户最新批次指令、产品硬约束、安全与权利约束、默认替换规范。仍无法消解时阻断该图并记录冲突，不自行选择风险更高的解释。

策略只覆盖其明确声明的范围。指定了替换值但没有声明重复实例、接触边界和去水印时，Skill 继续依据单图默认规范补齐；跨图去重和组合分配只在显式共享批次策略中补齐。`ReplacementPlan` 的每个关键决定都记录 `decisionSource`，支持 `per_image`、`batch` 和 `autonomous` 混合出现。

单图请求通过可选的 `replacementStrategy` 表达当前 Production Item 的显式策略。字段白名单和结构约束读取 `contracts/machine-rules.json`：

- `replacementValue` 与 `replacementCategory` 成对出现。来源分析 adapter 接收规范化后的单图策略，对指定值单独产生 `explicitReplacementEvaluation`；该值无需预先存在自主 `replacementPool`，仍必须通过类别、语义、视觉、权利和安全硬过滤；
- `forbidValues` 排除不允许选择的值，剩余目标继续由自主规则稳定选择；
- `preserve` 追加用户明确冻结的文字、关系、构图或文化锚点；
- `policyId` 与 `policyVersion` 只提供策略追踪，不单独构成执行动作。

策略列表先规范化排序再计算 Production Item 身份摘要。语义相同但列表顺序不同的请求可以幂等复用；同一 Production Item 改变策略内容时按身份冲突阻断。

`preserve` 与主要目标或依赖闭包重叠时，同一内容会被同时要求冻结和重绘。来源分析 adapter 为每个冻结值返回绑定策略原文的 `preserveConflictEvaluations`，其中使用组件 ID 记录与变更集的语义冲突。工作流校验每个 ID 都属于当前 changed set、布尔值与 ID 列表是否一致，以及证据是否覆盖全部策略值，再于生图前阻断冲突；证据不完整或内部矛盾时按外部分析失败停止。

### 2.1 来源画布与载体路由

来源分析先产出唯一 `sourceCanvasDecision`，再分析替换目标。路由只保留四种：

- `standalone_design`：来源本身就是独立画面，完整画布作为目标区域。
- `print_artwork`：来源是衣服、杯子、手机壳、海报框、包装等载体上的独立设计。根画布只取可印制设计区域，并执行提取与正视化；衣服版型、领口、袖子、模特、衣架、地板、房间、设备边框、商品阴影、布料褶皱、透视和摄影景深进入排除区域。
- `screen_content`：来源是截图、屏摄或设备界面。根画布只取内容区，裁掉黑色截屏框、设备边框、界面控件和屏幕外环境。
- `full_scene`：完整商品外观、穿搭或使用场景本身承担玩法时，保留完整场景。

用户明确说“只参考 T 恤/衣服上的图案、印花或设计”时直接使用 `print_artwork`。用户未说明时，以下信号有两项即可采用该路由：设计位于可印制表面；载体外有商品拍摄环境；同一设计重复出现在多件商品或屏幕预览；去掉载体后仍有完整阅读顺序。两种路由都成立且会改变成图范围时进入复核。

`print_artwork` 必须保留印花内部的文字层级、人物/动物/照片占位、拼贴网格、阅读顺序、遮挡、线条、网点、涂鸦、色板和装饰节奏。候选图输出干净、正视、无透视的独立平面设计，禁止生成 T 恤 mockup、穿着效果、商品陈列或拍摄背景。`screen_content` 同样保留内容区内部版式与阅读顺序。缺少目标区域、排除区域、必需动作或保留结构时，P1 在生图 API 前停止。

### 2.2 来源标记逐项处置

来源分析同时产出唯一 `sourceMarkPolicy`，明确已扫描全画布，并对每个可见标记逐项记录区域、类型、动作、依据和证据：

- 水印、平台标、账户标、伪签名和无关 Logo 只能使用 `remove`。
- 普通贴纸和装饰图标属于来源设计内容，使用 `preserve`；它们与替换身份绑定时使用 `synchronize`。
- 商标或品牌标默认使用 `preserve`。只有用户明确要求删除、标记属于被排除的商品载体、标记与旧身份形成依赖冲突或权利审核阻断时，才能使用 `remove`。
- 身份标记按依赖闭包使用 `preserve`、`synchronize` 或 `remove`，动作必须与新身份一致。

“画面干净”只表示没有未经授权的残留和来源污染。普通贴纸、装饰图标和已批准保留的商标不构成清洁失败。P1 Prompt 只能执行逐项策略，禁止把所有 Logo、贴纸或商标统称为要清理的内容。

## 3. 自主替换的决策流程

### 3.1 先抽取原图机制

仅抽取重构需要的信息：

- 核心笑点、情绪或传播价值。
- setup、turn、payoff 及因果方向。
- 主体数量、关系、姿态和接触结构。
- 核心非文字物体、容器、穿戴物和背景作用。
- 文字是否承担笑点，以及原始语言。
- 媒介、形态和构图骨架。

机制抽取后必须再完成两份 P1 上下文：

- `culturalReferenceDiscovery`：逐项核对角色造型与配色、服装、道具、身份符号和系列元素，输出 `identified / not_detected / uncertain`。识别到 IP 时保存名称、类型、画面角色和视觉证据；无法排除时保存候选并进入复核，不用通用人物或物体类别掩盖不确定性。
- `subjectContinuity`：冻结主体数量、物种或人物类型、性别呈现、年龄阶段、服装在玩法中的角色、反差机制和必须保持的特征。男性穿女仆装这类笑点需同时冻结性别呈现与服装角色，任一丢失都属于机制变更。

两份上下文与机制、组件图和替换计划一起编译为 `authoring-intent.json`。生图 Prompt 必须显式包含 IP/文化身份结论和主体连续性，它们不能只停留在分析日志中。

### 3.2 分类原目标

目标类别使用版本化枚举：

- 现实公众人物或偶像。
- 普通真人。
- 历史人物。
- 经典艺术作品主体。
- 明确角色/IP。
- 通用人物、动物、物体或食物。
- 承担主要画面职责的文字内容。
- 场景、背景或非文字视觉属性。
- 未知。

`unknown` 不能进入自动分配。该状态需要补充识别或人工复核。

### 3.3 决定替换对象

默认优先级：

1. 明确的主主体。
2. 承担笑点的核心非文字物体。
3. 能形成明显新鲜感的非文字视觉属性或场景。

原图文字默认冻结。只有显式策略授权，或笑点公式要求等价重写时，文字才进入替换集合。重写必须保持语义角色、时序和语言策略。

来源分析通过 `targetEligibility.textRewriteRequiredByMechanism` 记录笑点机制是否要求等价重写。缺少显式文字替换值且该证据不为 `true` 时，文字路由阻断。

### 3.4 生成替换值候选

候选值依次经过四道硬过滤：

1. **语义连续性**：物种/类别、年龄、性别、数量、关系、角色家族与笑点角色兼容。
2. **视觉兼容性**：姿态、轮廓、接触、穿戴、容器、视角和占位面积可实现。
3. **权利与安全**：来源可用于重构；现实身份、角色 IP、品牌和艺术作品按风险等级处理。
4. **显式共享约束**：仅当用户提供共享批次策略时，检查主题、比例、去重、IP 多样性和组合分配要求。

过滤后再做多样性分配，顺序不能颠倒。多样性不能牺牲笑点和画面关系。

权利或安全证据为 `review` 表示尚无法可靠判定。如果显式指定值仍为 `review`，或自主路由只剩该类候选，返回 `needs_input / NEEDS_REVIEW`；只有确定不兼容、被禁止或风险不通过时才使用阻断结果。

### 3.5 自主策略的类别规则

- 普通真人：由图片模型生成同年龄阶段、性别呈现、人数、关系和角色功能的新真人身份，并对完整人物及关联区域统一重绘。身份资产只在真人感、多人一致性或特定身份稳定性确有收益时作为可选辅助。
- 现实公众人物和偶像：替换为同类别、可准确命名的公众人物或爱豆；保持人物类型、组合结构、粉丝语境和媒介兼容，同步姓名、团名、应援文字、识别色和身份徽标。
- 历史人物和经典艺术主体：只有该身份是文化机制的必要锚点时才能保留语义身份，画面仍需整体重绘并进入权利复核。
- 明确角色/IP：允许自主选择同类别知名 IP，优先匹配角色家族、叙事功能、受众语境、姿态可供性和构图；同一 IP 家族内有可靠角色时可以优先选择家族内替换。身份本身承担不可替代的核心笑点时记录为保留例外。
- 通用动物、物体、食物：选择能维持姿态、关系和笑点的高辨识度新值。
- 文字：保持文字功能和语义类型。身份绑定文字随新身份更新、删除或中性化。P1 只更改被选中的主视觉文字及其必要依赖；与身份无关的非主视觉长文字默认进入 `frozenSet`。P3 再按确认模板图判定用户编辑权：有编辑价值时使用 `free_editable` 并原样进入 Prompt Template，没有独立编辑价值时才作为固定视觉文字保留。
- 场景或视觉属性：只有主体缺少有效替换价值，且改变该属性能形成稳定模板价值时使用。
- 未知：阻断自动生成。

自主场景路由把上述两个前置条件分别记录为 `targetEligibility.primarySubjectHasReplacementValue=false` 和 `targetEligibility.sceneChangeCreatesStableTemplateValue=true`；任一条缺失或不成立都在生图前阻断。单图策略明确指定场景替换值时，按策略优先级跳过该自主价值判断，指定值仍需通过完整硬过滤。

这里的“资产”指额外提供给模型的身份参考图。它是可选生成辅助，不是自主替换值的唯一来源。`prompt_only` 可以直接生成新的普通真人或可准确描述的同类主体。执行时必须完成完整身份替换和整图媒介统一，局部贴脸、旧身体残留或多人串脸均判失败。

### 3.6 显式共享策略下的跨图分配

本节默认不启用。用户明确提供跨图去重、身份多样性、IP 池、组合比例或专题锚点覆盖策略时，受该策略约束的生产项使用稳定分配：

```text
seed = batchId + templateKey + sourceIdentity
```

- 候选池未耗尽时，活动替换值保持唯一。
- 候选池耗尽后，按最低使用次数进行平衡复用。
- 批次策略可以设定角色家族、IP 池、性别、物种、主题和组合比例。
- 单图 rerun 在输入、规则版本、共享策略和 seed 不变时得到同一分配。
- 每次分配保存池版本、候选列表、过滤原因和最终选择，保证可解释。

没有显式共享策略时，每张图独立选择替换值，不读取其他生产项的身份、候选池使用次数、标题或版本 pin。

## 4. 依赖闭包

替换对象不能只按一个局部框处理。`changedSet` 必须包含目标及所有身份或结构依赖：

- 主体本体、脸、身体、服装和身份标记。
- 同一主体的重复实例、分格、剪影和局部特写。
- 派生颜色、纹理、图案和装备。
- 镜像、倒影、影子、屏幕内容和海报内嵌图。
- 与目标相接的手、爪、衣领、帽子、容器边缘和遮挡边界。
- 因替换而失效的文字标签、名字或身份符号。

`dependencyClosure` 必须是包含非空 `type` 和 `value` 的对象列表。结构损坏表示外部分析证据无效，返回稳定 `externalFailure`；列表为空表示替换范围尚无法可靠判定，返回 `needs_input / NEEDS_REVIEW`。

来源分析还必须产出唯一的 `subjectBindingAnalysis`。每个绑定组只记录关系类型、成员身份单元、必须随身份变化的组件和当前图证据：单主体专属配饰与主体进入同组；同一身份的重复实例进入同组；CP、搭档或固定组合使用 `bound_pair / bound_group`，全部成员及各自专属特征进入同组。身份换图默认把同图全部可辨识身份单元视为一个替换群组：即使它们在图中是 `independent`，也要同步替换，不允许一个换成新身份、另一个保留来源身份。

只要依赖闭包命中组内一个组件，就必须覆盖该组全部 `requiredComponentIds`；当身份单元数大于一时，闭包还必须覆盖所有绑定组的全部必需组件。漏掉任一成员、配饰、身份文字、影子或倒影时，P1 阻断且不编译可执行 Generation Package。

身份替换时，姓名、英文名、团名、称谓、号码、识别色和身份徽标进入同一依赖闭包。自主模式优先在模板图中删除或中性化这些身份文字；批次策略明确要求保留具体身份表达时，文字必须与新身份一致。后续开放主体槽时，如果确认模板图仍含具体身份文字，模板退回本阶段生成中性版本。

来源分析使用机器规则中的具名身份路由合同。普通真人记录 prompt-only 新身份与完整重绘依据；公众人物和知名 IP 的同类候选额外记录身份锚点、反锚点和玩法融合要求。每个身份候选提供与来源值、候选值双向绑定的 `distinctIdentity` 结论和依据；确定性门禁继续执行 NFKC、空白/标点折叠、大小写归一化和同一性修饰词清理，归一后来源值与候选值都必须非空且互不相同。`identityTopology` 精确列出 `dependencyClosure` 的全部身份组件，至少包含一个 `full_body`，组件 ID 必须唯一；文字组件 ID 还必须精确对应 `identity_text` 依赖。每个身份文字组件都需要 `remove`、`neutralize`、`exposeNeutralSlot` 或 `synchronize` 决策，并保存原值、结果、依据和高价值文字槽证据。`synchronize` 额外保存与选中身份双向绑定的关系类型，可表达直接姓名、英文名、团名、称谓、号码、识别色或徽标，无需把结果限制为候选全名原字符串。

身份路由对每个自主冻结项提供与当前拓扑绑定的冲突结论和组件依据。冻结项涉及新旧身份、身份文字或本次重绘组件时在 P1 阻断，Generation Package 不接收互斥的替换与保留命令。

身份文字决策继续接受 P2 视觉事实复核。视觉证据明确声明当前路由是否适用，同时确认旧身份文字已消失且新身份文字与替换值一致；任一确认失败都会派生为视觉硬失败。主体槽开放由机器规则声明的 subject 上传控件判定，控件 type 与 primary-subject semantic role 必须双向一致。主体开放时，标题、描述、自由内容、隐藏层、固定 Prompt 片段和非主体槽的 label、placeholder、默认值与推荐项保持身份中性；独立语义审计绑定这些完整文案并判定中性结果。`exposeNeutralSlot` 只对应机器规则声明的文字 prompt 控件。主体固定且身份文字已同步时，描述和固定 Prompt 可以使用新身份，标题继续服从当前标题合同。

`frozenSet` 包含未获授权改变的内容：

- 构图、镜头、版式和主体数量。
- 笑点机制、关系、动作和因果方向。
- 默认保留的文字、语言和符号拓扑。
- 与替换无关的背景、道具和视觉锚点。
- 原媒介与表现形态，除非策略明确要求改造。

## 5. 生图 prompt 的固定结构

Generation prompt 由下列段落编译，并把最终字面直接写入 Generation Package 的 `prompt` 字段：

1. **任务声明**：基于参考图完成整图重构，输出一张可独立使用的新模板图。
2. **替换目标**：明确旧目标的画面位置、实例范围和新目标内容。
3. **依赖闭包**：列出必须同步改变的重复实例、派生内容和接触边界。
4. **主体绑定**：逐组列出同步替换的成员身份单元和全部必换组件。
5. **目标画布**：逐字写入独立设计、印花提取、截图内容或完整场景路由，以及目标区域、排除区域和正视化/裁框动作。
6. **来源标记策略**：逐项写入水印、贴纸、装饰图标、商标与身份标记的 `remove / preserve / synchronize` 决策。
7. **冻结项**：列出需要保持的构图、关系、动作、文字、语言和视觉机制。
8. **六维视觉合同**：媒介、形态、边缘、色彩明暗、表面和构图逐项写明，不允许只写“保持原风格”。
9. **残留清除**：清理旧身份特征与旧轮廓；来源标记严格按逐项策略执行。
10. **空间关系**：穿戴、手持、遮挡、压合、前后层级、容器内部和接触点。
11. **输出要求**：一张图、尺寸、比例、完整画布、清晰度和禁止额外文字。

prompt 中的“改什么”和“保留什么”都必须来自 `ReplacementPlan`。生成器不能自行扩展替换范围。

P1 同时写入 `firstStageGate`：依赖闭包、主体绑定、六维视觉合同、来源目标画布、来源标记策略和最终 Prompt 六个汇总门禁必须全部为 `true`，并保存 `promptSha256`。汇总结论由七条机器资格证据推导：依赖闭包与图片操作目标精确对账、六维画风进入 Prompt、身份专属特征整组绑定、多主体全组同步替换、目标画布路由完整、来源标记逐项策略完整、最终 Prompt 与固定段落字面完全一致。P2 的 Generation Task 只能读取该冻结 `prompt`，不得重新拼接、删减或临时补写。这个结构对应官方 GPT Image 提示原则：复杂请求使用短标签或换行；具体描述材质、形态、纹理和媒介；编辑任务明确“只改 X、其余保持”；多图输入逐张说明职责。参见 [OpenAI GPT Image 提示指南](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide)。

批量信封的默认隔离、显式共享策略、`per_image > batch > autonomous` 优先级、稳定候选分配和逐项分辨读取 [批量隔离与共享策略合同](shared-batch-policy.md)。

网图像素只用于分析和参考。禁止局部复制、裁切粘贴或保留来源水印；即使替换区域较小，也要通过整图生成得到新的模板图。

## 6. 媒介与画面验收

每张生成图使用六维视觉合同验收：

| 维度 | 检查重点 |
| --- | --- |
| medium | 摄影、插画、拼贴、像素、手绘等媒介是否一致 |
| form | 体积、轮廓、比例、脸部数量和主体结构是否成立 |
| edge | 线条、轮廓、软硬边和抠图边缘是否统一 |
| colorAndShading | 色相、明度、光影、平涂或体积光是否匹配 |
| surface | 材质、纹理、噪点、纸张、屏幕或布料表现是否匹配 |
| composition | 版式、镜头、主体占比、留白和视觉顺序是否保持 |

还需检查：

- 主体具有“一眼可辨”的替换差异。
- 物种使用正向识别锚点，并排除容易混淆的反向特征。
- 表情符号、图标和文字按拓扑结构检查，不能只检查字符大意。
- 穿戴和持握包含覆盖、压住、遮挡、前后层级等接触证据。
- 摄影模板没有混入插画式重绘，插画模板没有混入摄影皮肤或镜头特征；混合媒介需要按区域声明。
- 全画布三轮扫描来源标记：显眼标记、半透明角标、嵌入屏幕或衣物的残留；逐项对照 `sourceMarkPolicy`，已批准保留的贴纸或商标保持合法。

## 8. 阻断条件

以下任一情况禁止自主进入生图：

- 目标类别为 unknown。
- 显式策略之间存在无法消解的冲突。
- 找不到同时满足语义和视觉兼容性的替换值。
- 文字承担核心笑点，但是否允许重写无法判断。
- 文化身份或 IP 是核心锚点，权利处理方式未确定。
- 替换依赖闭包无法确定，可能产生半替换结果。
- 原图机制依赖真实人物伤害、敏感身份或其他高风险表达。
