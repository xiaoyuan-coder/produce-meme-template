# ADR-0031：全量规范条款必须绑定可执行所有者

- 状态：Accepted
- 日期：2026-08-27

## Context

关键结果账本和历史经验矩阵覆盖了高价值结果与已知失败，但无法证明 Skill 所有可达 reference 中的每条规则都拥有代码所有者。规则仍可能停留在知识层，新增条款也可能在没有门禁和 Bad Case 的情况下进入发布包。

## Decision

建立 `normative-rule-registry.json` 作为 Skill 规范覆盖的机器事实源。扫描器对所有可达权威文档的每个非代码语义单元生成稳定 rule ID 与摘要；每个单元的执行家族必须经过显式审查并冻结，禁止使用首关键词或文档默认家族自动猜测。机器合同冻结全量逐单元映射摘要，新增或改写单元缺少审定映射时刷新失败。每个执行家族必须拥有真实代码或机器合同所有者、Good Case、Bad Case、历史经验，并在适用时绑定最终关键资格。

仓库测试精确重算权威文档集合、文件摘要和语义单元。新增指针、增加 ADR、改写或删除条款、删除代码 owner、删除测试、删除历史经验或破坏关键资格引用都会失败。文档不能自证执行完成。

## Consequences

- Skill 规则变化增加一次显式注册表审查，换取新增知识无法静默绕过代码和测试。
- 注册表按执行家族复用现有门禁和红例，避免为同一不变量复制大量测试。
- 关键结果账本、历史经验矩阵和全量规范注册表分别回答“当前结果是否合格”“已知失败是否回归”“全部可达规范是否有执行所有者”。
