# ADR-0026：生产前强制模板身份与独立作者合同审计

- 状态：Accepted
- 日期：2026-08-21

## Context

批量 1376–1382 暴露了三个可同时发生的失效模式：素材流水号直接成为正式模板 key；每张图的槽位候选通过同一组自证布尔值进入编译；生产、清理、商品展示和输出禁止项进入了用户可见 `promptTemplate`。现有正则形状检查、固定短语黑名单和分析对象内的 `valueGates` 无法形成独立证据链。

## Decision

### P0 模板身份门禁

公共生产 seam 在读取来源图摘要后，必须调用 `resolve_template_identity`。结果写入 `template-key-resolution.json`，并绑定来源图 SHA、proposed key、resolved key、注册表修订号、存量命中结果、冲突结果和语义 key 结果。

新 key 使用小写 kebab-case 的画面语义命名。素材号、批次日期和版本号只能作为 `productionItemId`。存量非语义 key 只有在注册表明确命中同一来源图摘要时才可继续使用。注册表不可用、来源不匹配、语义无效和 key 冲突分别使用稳定错误码停止生产。

### P4 独立作者合同审计

模板分析完成后，公共 seam 必须调用 `audit_authoring_contract`。审计请求绑定 Approved Image SHA、组件图、槽位候选、用户 Prompt 和视觉合同。审计结果写入 `authoring-contract-audit.json`。

每个槽位都需要独立绑定可见组件 ID，并重新裁决用户动机、视觉可见、模型可控和机制保留。编译器只消费该独立审计的结果，分析对象内的 `valueGates` 仅作为候选提交形状，不再决定槽位入选。

`promptTemplate` 只描述用户实际可替换的画面内容。媒介、构图、关系和稳定的正向视觉事实进入 `visualContract`；清理、商品展示和输出禁止项留在生产 sidecar。审计使用逐句职责分类，固定短语扫描只保留为早期辅助防线。

## Consequences

- P0 和 P4 各增加一个必须入谱系的 sidecar。
- 缺少注册表或独立审计 adapter 时采用 fail-closed。
- 恢复、最终化复算和发布验收必须同时校验两个 sidecar 的摘要与依赖。
- 批量隔离由每个 Production Item 的来源图 SHA、独立身份查询和独立作者合同摘要证明。
