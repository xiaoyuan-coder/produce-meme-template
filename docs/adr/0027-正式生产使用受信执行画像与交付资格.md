# ADR-0027：正式生产使用受信执行画像与交付资格

- 状态：Accepted
- 日期：2026-08-21

## Context

批量 1376–1382 证明字段合同、视觉合同和单元测试本身不足以约束实际执行。批处理脚本可直接注入 deterministic fixture generation、复制同一组审核结论，并将测试结果继续编译为正式 JSON。已有 doctor 只校验版本与 pin；P2、P4、P7 和拆分交付缺少统一的执行资格事实。

## Decision

### 正式执行画像

公共 `run_production` 增加 `execution_mode`。`recorded_replay` 保留确定性回放、测试和快速恢复能力，产物写入 `production-execution-profile.json` 并明确标记不可交付。`live_external` 在任何 Production Item 落盘和 Fal/OSS 调用前验证适配器拓扑：Aliyun OSS 包裹 Fal，视觉审核方法位于批准集合，作者分析与作者合同审计拥有不同方法身份。

正式模式还必须由 doctor 证明当前代码运行于已验证的安装发布包。source worktree 可运行回放和发布资格测试，不能直接获得正式交付资格。执行模式、画像摘要和 sidecar 同时进入 Production Manifest 身份；恢复时禁止切换模式或替换画像。

### 分阶段证据复核与交付门禁

P2 对账 Fal provider 和视觉审核方法身份，P7 对账 Aliyun OSS provider，P8 完成态重放当前执行画像、WAL、Approved Image、作者合同、视觉合同、Asset Receipt 和正式投影。拆分导出要求每条记录提供完成态 Production Manifest，并复核画像为可交付的 `live_external`；复制到独立路径的回放 JSON 不具备导出资格。

### 效率约束

执行画像属于内容寻址的 P0 身份事实。画像与请求不变时继续复用现有 generation WAL、候选图、Approved Image 和 Asset Receipt，重复执行不会新增 Fal 或 OSS 调用。批量入口继续采用逐项并发和大阶段屏障；单项失败只停止自身，执行画像变化只使对应 item 阻断。

## Consequences

- fixture、录制回放和自定义测试 adapter 仍可快速完成 P0–P8，用于测试与发布回放；其正式 JSON 只能作为内部证据。
- 历史 Production Item 缺少执行画像时 fail-closed，需按迁移路线重新运行。
- 正式生产调用方需要显式声明 `live_external`，使用受信适配器拓扑，并从已安装发布包运行。
- `gallery-template.json` 保持纯业务合同；交付资格继续留在 Production sidecar 和导出清单中。
