# 历史经验迁移追踪矩阵

## 1. 使用方式

每条经验都必须拥有唯一规则落点、机器门禁或 fixture。状态含义：

本文件保存领域迁移决定；当前可执行 test ID、fixture SHA、实现定位和发布状态统一由 `fixtures/regression/historical-experience-matrix.json` 管理，避免在规格与脚本间维护两份机器证据。

- `确认迁移`：当前业务口径与真实证据一致。
- `条件化迁移`：只在显式策略或特定图片风险下启用。
- `重写迁移`：保留能力，旧表达或旧阶段位置失效。
- `废止`：与当前职责或当前决策冲突。

## 3. 当前未闭合项

领域口径已经闭合到可以继续设计。当前正式数据、用户确认口径与现有 Schema 足以支持新 Skill 的 JSON 生产职责。`gallery-template-authoring-spec.md`、`gallery-template-import/README.md`、Worker 编译规则和 `inputSchema.image.extract` 的实际消费方式属于研发链路，不作为本 Skill 的完成条件；新 Skill 只保证字段合法、数据语义正确且不承诺未被正式数据合同声明的后端行为。
