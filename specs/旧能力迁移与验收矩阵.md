# 旧能力迁移与验收矩阵

## 1. 迁移原则

迁移单位是“能力与验收事实”，不按旧文件原样搬运。每项能力需要确定新归属、机器合同、fixture 和验收证据；重复规则合并到一个定义位置。

状态说明：

- `必须迁移`：新生产链路上线前必须具备。
- `重构迁移`：保留业务价值，按新事实源和新阶段重写。
- `条件化迁移`：只有用户显式提供共享策略或图片命中特定风险时启用。
- `合同编译`：只按正式模板 JSON 合同生成字段，不承担消费端实现。
- `独立入口`：保留能力，不进入生产主流程。
- `停止继承`：旧机制与新流程冲突。

## 3. 经验教训转成的硬门槛

### 3.1 结构通过不等于模板可用

每个模板需要四类独立结果：

- `schemaValidation`
- `semanticValidation`
- `visualContractValidation`
- `galleryContractValidation`

最终通过条件由四项证据共同计算。报告中的 `pass: true` 必须能定位到检查记录、字段或图像区域。

### 3.2 模板图是 P3 之后的唯一画面事实

回归测试需要主动构造这些错误：

- title 仍描述原网图人物。
- description 使用已被替换的物体。
- 槽位默认值来自网图，和模板图不一致。
- instruction 混入旧身份特征。
- cover/reference 指向不同 revision 的图片。

验证器必须拦截或将其标记为人工复核。

### 3.3 图片操作必须有清除语义

fixtures 至少覆盖：

- 主体替换后仍残留旧脸或旧身份颜色。
- 背景上传只叠加局部，没有覆盖旧背景。
- 蒙版填充保留原内部线条。
- 容器替换没有清除旧内容。
- 穿戴物漂浮，没有接触和遮挡。
- 分格中只替换了一个实例。

### 3.4 媒介不能漂移

fixtures 至少覆盖：

- 摄影模板被 instruction 要求画成插画。
- 插画模板混入写实皮肤或镜头语言。
- 混合媒介未按区域说明。
- promptTemplate 把锁定媒介暴露成用户槽位。

### 3.5 用户可见文案与内部术语隔离

title、description、槽位文案和 promptTemplate 中禁止出现生产过程术语。建立词表检查，并配合语义复核，避免仅靠关键词造成漏判。

## 4. 验收样本集

新 Skill 上线前建立固定回归集：

1. 历史 GoodCase：覆盖真人、动物、IP、文字梗、双格、多实例、穿戴、容器、背景和混合媒介。
2. 历史 BadCase：优先收录 8 月批次暴露的问题及 843 条数据三轮修复案例。
3. 边界样例：unknown 主体、文字是否可改不明确、权利不确定、替换池耗尽、显式策略冲突。
4. 版本样例：安装副本多文件、合同 major 不兼容、批次中途升级和模板 revision 错配。

每个样例保存：输入、期望阶段、期望通过/阻断原因、关键字段快照和必要图像证据。

## 5. 上线门槛

### 自动门槛

- 固定回归集 100% 符合预期结果。
- 全部 Schema、引用、版本摘要和状态迁移测试通过。
- 同一输入、策略、seed 和版本得到稳定 ReplacementPlan。
- 正式 JSON 不含审计字段、临时路径和非正式 URL 字段。
- 安装包与 release lock 文件清单和摘要完全一致。

### 业务门槛

- 真实批次影子运行后，逐图确认替换策略合理。
- 抽样评审覆盖每类目标、每类图片操作和每类媒介。
- 重点检查生成模板图与最终 JSON 的一致性。
- 对比旧流程，能力迁移矩阵中所有“必须迁移”项都有证据。
- 生产负责人确认可以切换入口，并保留旧版本只读回滚路径。
