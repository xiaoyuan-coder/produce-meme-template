# 历史批次经验冲突审计与策略加固清单

## 1. 结论

旧 Unified 已经积累了大量有效经验，当前主要有四类问题：

1. **经验停留在复盘文档**：文字角色、事实置信度、独立素材单元、同脸检查、区域水印风险图、审核证据新鲜度等内容尚未进入当前重构蓝图。
2. **同一问题存在多个口径**：槽位数量、自动重试次数、IP 替换、标题是否使用默认主体、照片像素权限等规则在不同批次里存在差异。
3. **旧阶段顺序改变了规则含义**：旧流程先分析来源图、再生成候选图；新流程先生成模板图、再编译模板数据。大量“候选目标、候选推荐项、候选图标题”规则需要重新命名和改写。
4. **静态门禁产生错误完成信号**：843/843 静态 PASS 后，第二轮抽样仍出现约 50% bad case。Schema、语义、视觉合同和正式 JSON 合同需要分别验证。

新 Skill 应保留历史能力的判断深度，同时更换规则组织方式：统一领域对象、唯一机器定义、分阶段证据合同、可失效的产物依赖图。

## 3. 需要统一的冲突规则

| 主题 | 旧口径 | 历史经验或新流程证据 | 建议统一口径 |
| --- | --- | --- | --- |
| 阶段顺序 | 第一阶段先写模板数据，第二阶段生成候选图 | 新流程先换图，模板图确认后再分析 | 网图分析只服务换图；模板数据只从已确认模板图编译 |
| 候选目标 | 从槽位中选择一个 `targetSlotId` | 新流程换图发生在槽位设计之前 | 使用 `sourceComponentId + replacementOperation` |
| 候选图用途 | 用单槽变化证明模板可编辑能力 | 新模板图承担默认视觉、reference 和 cover | 第一阶段只证明安全重构；用户编辑效果验证通过读取现成 JSON 的 T1 独立发起 |
| 替换值与推荐项 | 首个推荐项用于候选生成并成为默认值 | 替换对象未必成为用户槽位 | ReplacementPool 与 SlotSuggestionPool 完全分离 |
| 标题事实源 | 来源图分析后写标题，候选定稿后返修 | 多批次出现来源身份、节日和物种残留 | title 只读取 ApprovedTemplateImage 与开放槽位合同 |
| 标题主体名 | 高置信 IP 或默认主体写入标题 | 开放主体后专名会缩窄模板理解并造成默认身份残留 | title 统一使用画面机制、动作、关系、容器或场景组成的中性标题 |
| 专题标题经验 | 用户视角和活动动作已被验证有效 | 该经验面向专题运营标题 | 专题标题与单模板 title 分开维护 |
| 槽位下限 | 每个模板至少两个高价值槽位 | 用户确认绝大多数图片会有多个槽位，同时允许穷尽分析后的真实单槽例外 | 常态至少 2 个且通常约 3 个；复核后确实只有一个高价值变量时允许 1 槽并保存证据 |
| 槽位上限 | 2–4 个，部分文档允许第 5 个装饰槽 | 部分图片确有五个独立高价值内容 | 上限 5 个；第五个必须通过价值与稳定性门禁，独立素材不为控件数强行合并 |
| 推荐项数量 | 每个逻辑槽恰好三个推荐项 | 图片上传槽不适用，复杂槽可能缺少三个可靠值 | 数量由产品合同决定；语义层只接受可靠、同轴、非默认值 |
| 原语种保持 | 来源图可见文字默认保持原语种 | 第一阶段可能有明确文字替换策略 | 网图到模板图默认保留；模板图确认后以实际模板文字为事实 |
| 全部文字保持 | 精确文字合同要求保留来源文字 | 水印、账号、品牌和正文经常混在一起 | 先分类文字角色，再分别 preserve、expose、replace、remove 或 review |
| 主体像素权限 | 用户图像素、皮肤、光影统一不进入结果 | 摄影抠图、旧照片和混合媒介需要区域化处理 | 按区域和 imageOperation 路由不同权限 |
| instruction | 放入构图、身份、清洁、接触和脚手架 | 新规范只保留媒介、卖点、可选色彩 | instruction 按正式 JSON 合同编译，公共规则由生产编译器承担 |
| promptTemplate | 旧示例包含固定画风和配色；部分新规范又收窄为只表达槽位 | 用户确认全文是可自由编辑的自然语言生图提示词 | 包含全部开放槽位与未入槽但仍有编辑价值的内容；固定呈现维度和生成纪律退出 promptTemplate |
| 自动重试 | 同类失败两次停止或三次停止 | 不同失败的成本和可修复性不同 | 按 `failureClass` 配置预算 |
| 真实用户生图 | 高风险模板进入真实生图门禁 | 用户确认可用生图测试模板 JSON，并要求显式单独唤起 | 保留为 Skill 的 T1 独立入口；测试记录与正式 JSON 分离，测试状态与生产状态相互独立 |
| OSS 字段 | 当前正式数据与 2026-07-30 Schema、843 条最终数据使用 `cover`；Unified V1.7.1、旧 UAT 和管理台专题导出仍使用 `coverUrl` | 用户确认当前正式口径为 `cover`，运行代码暴露出待清理的版本残留 | 新 Skill 正式输出固定 `cover` 与 `referenceImage`；`coverUrl` 作为旧链路冲突 fixture，不做双写兼容 |
| IP 替换 | 角色 IP 换同类知名 IP，爱豆使用同类池 | 0.62.4 与“穿点好运”已验证同类知名身份整图重绘 | 无策略时允许自主同类替换；知名 IP、爱豆和普通真人分别路由，记录锚点、批次分配与身份文字闭包 |

## 4. 第一阶段换图策略需要加固

### 4.1 从候选槽位改成来源组件操作

`ReplacementPlan` 增加：

- `sourceComponentId`
- `sourceComponentRole`
- `replacementOperation`
- `replacementValue`
- `decisionSource`
- `changedSet`
- `frozenSet`
- `dependencyClosure`
- `riskChecks`
- `failureBudgetProfile`

`replacementOperation` 至少区分身份、物体、嵌套内容、场景、视觉属性、授权文字替换和文化锚点保留。P3 再决定这些组件是否成为用户槽位。

### 4.2 来源身份与模板身份双账本

- `sourceIdentity`：网图身份，只服务替换、权利和残留检查。
- `templateIdentity`：模板图实际身份，是正式文案和默认值的依据。

硬门禁：

- 网图专名不能自动进入正式用户字段。
- 模板身份不确定时使用可见中性名称，或返回替换阶段。
- 模板身份变化后，P3–P8 全部失效。
- 旧身份进入 `forbiddenLegacyClaims`，扫描 title、description、Prompt、标签与隐藏约束。

### 4.3 文字区域账本

每个可见文字区域记录位置、阅读顺序、精确文字、语言、大小写、数字、标点、符号拓扑、角色与处理动作。

文字角色固定区分：

- `content`
- `attribution`
- `watermark`
- `brand_mark`
- `ambiguous_mark`

处理动作固定区分：

- `preserve`
- `expose`
- `replace_authorized`
- `remove`
- `review`

文字笑点需要表达谐音、共字双关、隐藏展开、文字—物体绑定、字内图片蒙版、翻译等价和符号拓扑。

### 4.4 身份拓扑与依赖闭包

除主体、影子、倒影和重复实例外，还要覆盖：

- 姓名、身份文字、Logo、粉丝名、应援色和徽标。
- 不同姿态的同身份实例。
- 同一来源照片的重复裁切。
- Q 版分身、浅色印花、剪影和背景头像。
- 穿戴、持握、容纳、遮挡、镜像、拟态和融合边界。
- 嵌套屏幕、相框、海报、包装和容器内部。

同时维护 `identityBindingGroup` 与 `assetBindingGroup`。

### 4.5 水印与品牌区域风险图

新规范增加：

- 四角、边缘、半透明层、主体覆盖区和高亮区扫描。
- 水印、账号、签名、二维码、平台标与品牌包装分别定位。
- Prompt 指定目标区域的正向新内容。
- 生成后在原尺寸执行全画布复核。
- 同一区域重复失败时升级为区域重建或返回替换方案。

### 4.6 六维合同加四类专项

六维合同继续保留 `medium / form / edge / colorAndShading / surface / composition`。

专项增加：

1. `identityTopology`：重复实例、派生实例、旧身份残留。
2. `textTopology`：字符、语种、区域、换行、符号结构。
3. `contactGeometry`：穿戴、持握、遮挡、容器与解剖。
4. `cleanAssetMap`：水印、品牌、平台标和残留区域。

生成器只创建 `pending_review`。审核通过由证据计算。

### 4.7 按失败类型配置重试

| failureClass | 默认动作 |
| --- | --- |
| 网络、429、5xx | 复用 request ID，有限重试 |
| 合同错误、422 | 返回 ReplacementPlan 或 GenerationPackage |
| 身份不匹配 | 修订身份锚点或替换值 |
| 文字错误 | 修订文字区域和符号合同 |
| 水印残留 | 升级区域重建 |
| 机制破坏 | 返回替换方案 |
| 媒介漂移 | 修订六维合同 |
| 接触失败 | 修订接触和遮挡合同 |

每类错误独立配置 `maxAutomaticRetries`。相同失败再次出现时优先改变合同。

### 4.8 条件化跨图审核

批量提交默认只运行逐图审核，不生成跨图组合分配、标题唯一性或汇总报告。用户明确提供共享批次策略时，才按该策略激活跨图身份多样性、IP 分配、标题去重或专题锚点覆盖检查；共享检查不能替代任何单图门禁。

增加身份指纹、替换池使用次数、物种/人物/IP 分布和组合多样性报告，拦截同脸、相同发型姿态、IP 重复和替换值失衡。

## 5. 标题策略需要统一

### 5.1 唯一事实源

title 只读取：

1. ApprovedTemplateImage 的可见事实。
2. TemplateAnalysis 中已确认的动作、关系、容器、文字和视觉钩子。
3. EditableTemplateSpec 中的开放范围。

网图标题、来源身份、来源节日和旧候选文案只作为禁止泄漏项。

### 5.2 五个门禁

1. `templateGrounded`：能在模板图核验。
2. `usageMotivation`：表达用户想获得、送出、记录或展示的结果。
3. `spokenNaturalness`：朗读自然，无分析术语和对象堆叠。
4. `slotPortability`：开放槽位替换为最大差异值后仍成立。
5. `batchDistinctiveness`：与同批标题的开头、动词、尾词和句法有区分。

### 5.3 标题取材顺序

优先选择核心动作或关系、视觉钩子或容器、用户结果或情绪、必要画内主文字。

具体 IP、人物姓名、年龄、性别、物种、发型、服装和身份配色不进入标题骨架。标题始终保持中性。

### 5.4 保守命名

物种、商品、IP、食物或文字无法高置信确认时：

- 使用直接可见的通用名称。
- 保存被拒绝的具体名称和证据不足原因。
- description、槽位默认值和模板图事实保持同一称呼；title 继续使用中性机制或场景表达。

### 5.5 批次审核

- 精确去重与近似句式聚类。
- 开头、动词、尾词和标点节奏统计。
- 生产/分析术语扫描。
- 默认槽位值泄漏扫描。
- `forbiddenLegacyClaims` 泄漏扫描。
- 标题墙人工快速朗读入口。

5–14 个汉字作为柔性范围，不能单独决定 PASS。

### 5.6 专题标题与模板 title 分离

专题运营标题强调用户认领和活动动机；模板 title 强调单张模板视觉钩子和编辑后稳定性。两类标题使用不同 reference 和 fixture。

## 6. 槽位挖掘需要统一

### 6.1 先做组件图

每个显著组件记录角色、证据、用户意图、视觉显著性、独立性、模板价值、生成稳定性、依赖风险和处置。

组件角色至少区分主体、物体、配饰、服装、背景、容器、嵌套内容、文字、叠影、影子、剪影和装饰。

### 6.2 四个数量分别计算

- `identityCount`：不同身份数量。
- `visualInstanceCount`：可见实例数量。
- `uploadAssetCount`：用户需要提供的独立素材数量。
- `inputControlCount`：前端最终控件数量。

同类主体、共享文案和相邻位置不能直接触发合并。独立裁切、独立容器、独立身份、独立位置和可单独替换是拆分强证据。

### 6.3 槽位数量改为产品预算

确认口径：

- 正式模板保留 2–5 个高价值内容槽，常态目标约 3 个。
- 首轮只发现一个槽位时，继续复核内容物、颜色、文字、服装、道具、场景和嵌套内容。
- 必要独立素材可以使用正式 JSON 合同支持的有序集合控件，集合仍按一个用户控件计数并保留独立素材边界。
- 少于两个真实高价值槽位或必要输入无法表达时保持 DRAFT 并报告能力缺口。
- 低价值装饰先退出，必要身份和图片输入保持完整。

### 6.4 图片输入按操作区分

至少区分：

- `identity_reference`
- `embedded_image_content`
- `edit_target`
- `scene_reference`
- `texture_reference`
- `composition_reference`

框内整张照片读取人物、背景、动作与构图，外层容器归模板；主体身份只读取身份线索；背景场景不能触发人物身份提取。

### 6.5 文字槽先分组

- 空间、字号、颜色、载体或语义独立的文字分别记录。
- 同一句版式换行可以保持一组。
- 翻译依赖使用 `translation_equivalence`。
- 源文本变化后，依赖文本重新计算并复核。
- 审核覆盖固定文字和开放文字。

文字槽额外执行三类准入门禁：

1. 身份绑定文字，包括姓名、角色名、称谓、团名、号码和身份标签。
2. 主要视觉文字，包括文字卡、主标题、核心口号和承担笑点的关键句。
3. 长文本内具有独立语义和清晰编辑价值的关键词或短语。

海报微字、装饰性外文、版权或出处信息、氛围填充文字默认锁定或清理。长段落不能整体成为槽位；优先抽取关键词、短语或视觉收尾句。文字槽按角色和版面设置长度上限，超长默认值、推荐项和用户输入在编译前阻断。

### 6.6 主体与身份文字执行生产侧去冲突

内部分析记录主体与姓名、英文名、团名、称谓、号码、识别色和身份徽标的依赖关系，用于决定模板图与正式 JSON 的安全默认态。该关系不作为自创字段写入正式 JSON。

正式模板采用以下规则：

1. 主体开放时，返回模板图阶段，把依赖的具体身份文字替换为中性文字或移除。
2. 身份文字具有独立编辑价值时，可以开放短文字槽，默认值使用 `PORTRAIT`、`YOUR NAME` 等与主体无冲突的中性值。
3. 身份文字缺少独立编辑价值时保持中性固定文字，不为它创建槽位。
4. title、description、promptTemplate、inputSchema、instruction、lockedConstraints 和 preserve 全量扫描旧身份专名。
5. 正式 JSON 合同未提供联动字段时，不写身份解析、自动同步或别名推导承诺。

“洛天依复古绘图窗口”按新生产规范应改成中性模板：title 使用“复古像素绘图窗口”，标题栏默认文字使用 `PORTRAIT` 等中性值。主体槽继续开放；标题栏文字只有通过高价值门禁时才作为独立短文字槽。用户只替换主体时，默认数据不会残留 `洛天依` 或 `Luo Tianyi`。

### 6.7 高价值门禁

槽位同时满足：

1. 用户有明确修改意图。
2. 修改结果一眼可见。
3. 修改改变内容、表达、关系或玩法。
4. 正式 JSON 合同可以表达，生成模型能够稳定控制。
5. 修改后仍保留模板核心机制。

显著主体、完整照片、主文字、核心物件、成套服装、互动对象、嵌套内容和主题装饰都可以成为高价值槽。轻微渲染参数进入隐藏层。

### 6.8 推荐项规范

- 默认值与推荐项分别维护。
- 推荐项沿同一语义轴展开。
- 每项经过姿态、容器、接触、媒介和机制兼容检查。
- 不使用“用户自定义、简洁款、复古版”等机械补数值。
- 纯图片上传控件可以没有文本推荐项。
- 业务 Schema 要求固定数量时由编译器适配；可靠值不足时进入复核。

SlotSuggestionPool 只服务用户编辑，ReplacementPool 只服务模板图重构。

## 7. Prompt 与隐藏约束需要修改

### promptTemplate

- 表达全部结构化开放内容，并保留没有入槽但仍具有自由编辑价值的画面内容及自然关系。
- 固定媒介、构图、比例、材质、光影和清洁要求退出用户层。
- 默认值与全部推荐项逐项代入后语法自然。
- 两种编辑模式最终输出完整 `resolvedPrompt`。

### instruction

按正式模板 JSON 合同编译，只保留媒介、模板独有卖点和可选色彩层级。旧版长身份、清洁、冲突、输出和自检脚手架退出每条模板。

### lockedConstraints 与 preserve

- `lockedConstraints` 声明构图、镜头、媒介、材质、艺术比例和层级等维度。
- `preserve` 保存换开放内容后仍需成立的语义锚点。
- 开放槽位默认内容不能被 preserve 锁死。
- 抽象短句需要对应 TemplateAnalysis 中的结构证据。

### 编译冲突审计

- 只有实际携带图片的 `subject` 槽生成身份绑定。
- `prompt` 槽不能扩写成上传主体。
- 身份体型与艺术头身比分别表达。
- 同一角色位置只有一个权威数据源。
- remove 内容不进入 preserve 或正向 Prompt。
- 固定主体类型、数量和组合不被通用身份规则放开。
- 语言顺序与 inputId、区域和模板图事实一致。

## 8. 生产与维护能力需要补强

### 8.1 批次成员与写入边界

每个批次建立：

- `batch-membership-manifest.json`
- `batch-write-boundary.json`
- `current-revision-index.json`

目录扫描只负责发现文件。批量写入校验批次根、case allowlist、租约、写前 SHA 和写后漂移。

### 8.2 产物依赖图

建立 `artifact-graph.json`：

- ReplacementPlan 变化使 P2–P8 失效。
- ApprovedTemplateImage 变化使 P3–P8 失效。
- TemplateAnalysis 变化使 P4–P8 失效。
- 槽位或文案变化使相应下游失效。
- 图片 SHA 不变的 metadata 修订可以复用 OSS URL。

### 8.3 审核证据新鲜度

视觉审核绑定 GenerationPackage SHA、模板图 SHA、证据图 SHA、审核方法版本和审核时间。上游哈希变化后旧审核回到 `pending_review`。人工例外保留原失败结论，只授权明确动作。

### 8.4 生图任务恢复

API 返回 request ID 后先写 WAL，再轮询任务。网络重试复用同一任务和 request ID。

### 8.5 工具链能力清单

批次开始前检查编译器、Schema 验证器、视觉合同验证器、OSS finalizer、正式 JSON 合同快照、版本与文件摘要。缺失能力提前阻断，兼容模式声明替代能力和差异。

### 8.6 正式输出边界

新 Skill 的正式生产交付物只有完成 URL 回填的模板 JSON。生产 sidecar、审核记录、测试状态和运行时能力说明不进入正式 JSON。真实用户编辑与生图测试由本 Skill 的 T1 独立入口执行，需要用户明确指定已落盘 JSON。T1 拥有独立状态与产物目录，生产流程只包含 P0–P8。

## 11. 业务决定更新

### 决定一：槽位数量，已确认

正式模板使用 2–5 个高价值槽位，常态约 3 个。低价值装饰不能用于补数；少于两个真实高价值槽位时继续分析或保持 DRAFT。

### 决定二：自主替换，已确认

无批次指定策略时，Skill 按同类连续性自主选择替换值：真人换真人、二次元 IP 换同类知名 IP、猫换猫、狗换狗、文字换同类文字、物体换同类物体。普通真人允许 `prompt_only` 生成新身份并整图重绘；身份资产是可选质量辅助。知名 IP 同类自主替换继续沿用历史已验证策略。

### 决定三：中性标题，已确认

title 使用画面机制、动作、关系、容器、视觉钩子或场景组成的中性标题。具体 IP、人物姓名和可替换主体特征不进入 title。

### 决定四：正式交付边界，已确认

生产入口 P0–P8 负责生成、校验、上传回填并落盘正式模板 JSON。测试入口 T1 读取用户明确指定的现成 JSON，模拟编辑并真实生图，使用独立任务状态和产物目录。前端、后端、自动身份识别、运行时联动和数据库导入在职责范围外。生产侧通过中性模板图和中性 JSON 默认态解决身份文字冲突。
