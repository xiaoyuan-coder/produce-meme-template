## 4. 明确发现的权威冲突

| 冲突 | 证据 | 当前处理 |
| --- | --- | --- |
| 批量是否默认共享策略 | 旧批次有跨图 IP 分配、人物多样性、标题去重和汇总 | 当前用户口径优先；默认逐图隔离，显式共享策略才启用跨图规则 |
| 槽位下限 | 旧文档有“至少 2 个”和“允许单槽”两套口径 | 常态 2–5、通常约 3；穷尽分析后允许有证据的 1 槽例外 |
| Prompt Template 范围 | 旧规范一度收窄为“只表达槽位” | 当前口径与 843 条修订证据优先；包含全部槽位和未入槽但仍可自由编辑的内容 |
| 标题是否写默认主体/IP | 多批次允许确认 IP 进入标题 | 当前统一使用中性标题，执行最大差异输入测试 |
| 画面硬失败能否人工放行 | 全家出游旧批次允许失败候选人工例外 | 当前硬失败必须重做；人工只裁决风险和歧义，不能覆盖可观察违约 |
| 正式封面字段 | 当前正式数据、2026-07-30 Schema 与 843 条数据使用 `cover`；Unified V1.7.1/UAT 和管理台导出代码残留 `coverUrl` | 当前正式输出采用 `cover`；`coverUrl` 记为旧链路版本冲突 |
| 真实生图测试位置 | 旧流程把候选/测试做成阶段门禁 | 生产模板图生成仍属主流程；现成模板 JSON 的用户编辑测试为独立 T1 |
| instruction 详细程度 | 843 条数据写六维长合同；8 月 14 日新规范要求三段式精简 | 六维事实留在分析/审计；正式 `instruction` 只按冻结业务合同编译 |
