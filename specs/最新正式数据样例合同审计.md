## 3. 已验证的新口径

### Prompt Template

两份 Prompt Template 都包含全部三个开放槽位，同时保留服装、白底、装饰、人物层级和位置关系等非槽位画面内容。这证明当前正式数据支持：

- 结构化槽位编辑。
- 对整段自然语言执行自由编辑。
- 没有入槽但仍具编辑价值的画面内容继续保留在用户可见描述中。

### Prompt Enhancement

- 爱心样例 `instruction` 为 122 个字符。
- 婚礼样例 `instruction` 为 142 个字符。
- 两者都采用“媒介 / 卖点 / 色彩”三段式并低于 150 字。
- `lockedConstraints` 使用维度指向，不在每条约束中复述整张图。
- `preserve` 保存模板玩法关系。

### 简洁默认值

- 爱心样例默认值分别为 4、4、10 个字符。
- 婚礼样例默认值分别为 2、2、10 个字符。
- 全部处于当前“中文优先 2–8 字、原则上不超过 12 字”的范围或允许边界内。

## 5. 权威使用方式

两份样例承担三种角色：

1. 正式 JSON 字段形状和字段顺序的当前样例。
2. 当前 Schema 的通过样例。
3. 历史语义冲突的回归输入。

它们不作为可直接复制的标题、描述、槽位内容或整段 Prompt 模板。新 Skill fixtures 应保留原样作为 bad/input fixture，再建立符合当前中性标题、数量一致性和槽位权限规则的 expected fixture。

## 6. 旧流程字段投影

两份样例中的 `candidateScope`、`runtimeRequirements`、`templateSource`、`inputSemantics`、`suggestionRationales` 和 `optimizationAudit` 属于旧生产分析、校验或审计信息。它们可以继续存在于内部 sidecar，不进入新 Skill 的正式 JSON 投影。完整分类与最小投影验证见《正式 JSON 字段消费与旧流程字段审计》；仅保留 `metadata.tags` 后，两份样例仍通过当前 Schema。

两份样例的正式运行字段还各有 5 处“候选图”旧流程用语：两个 subject 槽的 `image.hint`、两个 `image.extract` 和 `promptEnhancement.instruction`。新 Skill 编译时统一改成“参考图”或“模板参考图”。`hint` 对用户可见，更需要清除生产术语；`extract` 虽然只留档，仍应与新领域语言一致。
